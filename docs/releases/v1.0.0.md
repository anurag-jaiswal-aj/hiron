# Hiron v1.0.0 Release Notes

**Release Date:** July 31, 2026  
**Version:** v1.0.0  
**Compatibility:** Initial Stable Release

---

## Highlights

- **Multi-Tenant Scoping**: Header-enforced tenant context resolution and database Row Level Security (RLS) isolation.
- **Automated Resume Parsing**: spaCy NLP text extraction pipeline supporting PDF (`pdfplumber`) and Word (`python-docx`) formats.
- **AI Fit Scoring Engine**: Multi-dimensional candidate evaluation algorithm generating fit scores (0–100), explanations, and recommendation bands.
- **pgvector Semantic Search**: Cosine similarity vector search backed by 1536-dimensional OpenAI embeddings (`text-embedding-3-small`).
- **Kanban Pipeline Management**: Interactive hiring stages, candidate transition APIs, and immutable stage history auditing.
- **Security & Compliance Hardening**: Asymmetric RS256 JWT authentication, Argon2id password hashing, HTTP security headers, request size limits, and audit logging.
- **Production Infrastructure**: AWS Terraform IaC, multi-stage non-root Docker builds, and automated GitHub Actions CI/CD workflows.

---

## Overview

Hiron is built using a clean, four-layer architecture:

$$\text{FastAPI Routers} \longrightarrow \text{Service Layer} \longrightarrow \text{Repository Layer} \longrightarrow \text{SQLAlchemy / PostgreSQL}$$

All operations execute under header-enforced tenant isolation (`X-Tenant-ID`) with Role-Based Access Control (`org_admin`, `recruiter`, `member`).

---

## Major Features

- **Multi-Tenant Isolation**: Header-scoped tenant context (`TenantIsolationMiddleware`) and database Row Level Security (RLS) enforcement across entities.
- **Resume Processing Pipeline**: Document upload (PDF/DOCX), text extraction via `pdfplumber` and `python-docx`, spaCy NLP entity parsing, and candidate profile enrichment.
- **AI Candidate-Job Scoring**: Multi-dimensional candidate fit scoring engine evaluating Technical (40%), Experience (35%), and Education (25%) dimensions with fit score persistence, explanations, and recommendation bands (`strong_hire`, `hire`, `consider`, `no_hire`).
- **Semantic Vector Search**: Cosine similarity vector search backed by `pgvector` for candidate-by-job search, job-by-candidate search, and hybrid query filtering.
- **Kanban Recruitment Pipeline**: Hiring stage movement API, candidate pipeline stage transitions, and immutable stage history auditing (`CandidateStageHistory`).
- **Recruitment Analytics**: Summary overview counters (open jobs, total candidates, scored candidates, shortlisted candidates), score distribution stats, and activity feeds.
- **Audit Trails**: Immutable `AuditLog` records tracking user actions, target entity types, IP addresses, and state changes.
- **AI Token & Cost Monitoring**: `AIUsageLog` records tracking LLM prompt/completion token consumption, operation breakdown, and USD cost accounting.
- **Post-Launch Maintenance**: System status diagnostics, cache management (`app_cache`), expired token purging, and AI scoring quality metrics via `/api/v1/maintenance/*`.

## Architecture & Modules

The backend application structure consists of the following modules under `apps/api/hiron/`:

- `hiron.auth`: JWT RS256 token generation/validation and Argon2id password hashing.
- `hiron.tenants`: Tenant provisioning and tenant context state resolution.
- `hiron.users`: User CRUD and role-based authorization check utilities.
- `hiron.jobs`: Job requisition CRUD, skill mapping, and default 5-stage pipeline generation (`Sourced`, `Screened`, `Technical Interview`, `Offer Extended`, `Hired`).
- `hiron.candidates`: Candidate profiles, experience records, and candidate-job assignment junction (`JobCandidate`).
- `hiron.resumes`: Document storage management (S3 interface) and resume text extraction.
- `hiron.embeddings`: OpenAI `text-embedding-3-small` vector generation and pgvector mapping.
- `hiron.scores`: AI candidate-job fit scoring engine (`AIScoringEngine`) and current score versioning.
- `hiron.search`: Cosine vector similarity search repository and saved query persistence.
- `hiron.pipeline`: Pipeline stage movement transitions and stage history audit logging.
- `hiron.notes` & `hiron.tags`: Candidate notes with private visibility flag and candidate tag organization.
- `hiron.dashboard`: Analytics summary aggregation and score distribution statistics.
- `hiron.audit`: Audit log persistence, event filtering, and entity history retrieval.
- `hiron.ai_usage`: Token usage tracking, cost calculations, and operational summaries.
- `hiron.performance`: Connection pool configuration, eager loading (`selectinload`), and in-memory LRU cache manager (`app_cache`).
- `hiron.security`: Security headers middleware, payload size limiting, and security audit generator.
- `hiron.maintenance`: Operational status checks, cache flushing, expired token cleanup, and AI quality diagnostic metrics.

## Security Controls

- **JWT Authentication**: Asymmetric RS256 signing using RSA 4096-bit keypairs with short-lived access tokens and refresh token rotation.
- **Password Security**: Argon2id password hashing with custom iteration parameters and high-memory cost bounds.
- **HTTP Middleware**:
  - `SecurityHeadersMiddleware`: Enforces HTTP Strict Transport Security (HSTS), frame protection (`X-Frame-Options: DENY`), MIME sniffing protection (`nosniff`), and Content Security Policy (CSP) headers.
  - `RequestSizeLimitMiddleware`: Rejects incoming HTTP request bodies exceeding 10 MB.
- **Data Isolation**: Application queries are scoped by `tenant_id` foreign keys and enforced via PostgreSQL Row Level Security policies.

## Setup & Deployment Instructions

1. **Database Schema Initialization**:
   Apply Alembic migrations to create tables and enable the `vector` extension:
   ```bash
   uv run alembic upgrade head
   ```
2. **Environment Configuration**:
   Copy `.env.production.example` to `.env` and set production secrets, database URL, and OpenAI API keys.
3. **RSA Keypair Generation**:
   Generate RSA 4096-bit private and public keys for RS256 JWT signing:
   ```bash
   openssl genpkey -algorithm RSA -out keys/jwt_private.pem -pkeyopt rsa_keygen_bits:4096
   openssl rsa -in keys/jwt_private.pem -pubout -out keys/jwt_public.pem
   ```
4. **Terraform Infrastructure Provisioning**:
   Initialize and apply Terraform configurations:
   ```bash
   cd infra/terraform
   terraform init
   terraform apply
   ```
