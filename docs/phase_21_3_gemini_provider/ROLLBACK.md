# Rollback Procedure for Gemini Embedding Implementation

## Reverting the Active Provider
The implementation safely retains both providers side-by-side. Rollback is a purely configurational operation.

To rollback to OpenAI:
1. Ensure `.env` or production Vercel configurations have `OPENAI_API_KEY` set.
2. Change the AI Provider flag:
   ```env
   AI_PROVIDER=openai
   ```
3. Restart the application or trigger a Vercel redeployment to reload `get_settings()`.

## Code Rollback (Hard Revert)
If a structural revert is necessary:
1. Revert `apps/api/hiron/core/config.py` to remove `gemini_*` flags.
2. Revert `apps/api/hiron/embeddings/generator.py` to `HEAD^` to strip the `httpx` HTTP calls.
3. Delete `apps/api/tests/test_embedding_generator_gemini.py`.

## Data Consistency
**WARNING**: Vectors generated by `gemini-embedding-001` are mathematically disparate from vectors generated by `text-embedding-3-small`. Cross-model cosine similarity searches between OpenAI and Gemini generated vectors will yield arbitrary or inaccurate scores.

Rollback of provider requires triggering a batch script to re-embed all `Resume` and `Job` text using the restored provider if they were embedded by Gemini during production traffic.
